# راهنمای انتشار عمومی WordRava نسخه 1.1.1

این راهنما در ۲۰۲۶/۱۱/۲۶ با مستندات رسمی OpenAI بررسی شده است. [English guide](MARKETPLACE_RELEASE.md).

**اصلاح سازگاری با Personal:** بستهٔ اصلاح‌شدهٔ ۱.۱.۱ را از
[صفحهٔ دانلود](https://wordrava.shayanostovar.com/download) یا
[انتشار تأییدشده در واردکننده](https://github.com/shayanostovar/WordRava-for-ChatGPT/releases/tag/mcp-v1.1.1-import-validated)
دریافت کنید. schema هر دو فایل manifest برابر `1.0.0` است؛ این شماره مستقل از
نسخهٔ محصول `1.1.1` است. یادداشت انتشار فقط در `extensions.com.openai.publication` قرار می‌گیرد.
بستهٔ اولیه schema نامعتبر `1.0.2` داشت و اصلاح اول هنوز شامل فیلد نامعتبر
`review.release_notes` بود. این بسته جایگزین هر دو شده، در واردکنندهٔ واقعی افزونهٔ
خصوصی پذیرفته شده و فایل‌های ذخیره‌شدهٔ آن دوباره بررسی شده‌اند. اتصال حساب از طریق
OAuth و داوری انتشار عمومی، مراحل جداگانه‌اند.

## دقیقاً چه چیزی آماده شده است؟

بسته WordRava یک **Agent Plugin** با فایل‌های `plugin.json` و `mcp.json` و همان لوگوی اصلی ارسالی است. این بسته به سرویس MCP عمومی WordRava وصل می‌شود. طبق [راهنمای ساخت بسته](https://developers.openai.com/plugins/build/plugins)، قالب فعلی برای فهرست عمومی مشترک ChatGPT و Codex معتبر است. نصب محلی یا مارکت‌پلیس یک مخزن، مسیر جداگانه‌ای برای توسعه و توزیع تیمی است.

انتشار کد و سرویس، به معنی تأیید OpenAI نیست. نام فایل شامل `review-draft` است، چون هویت ناشر، اطلاعات واقعی داوری و تأیید نهایی هنوز باید در حساب مالک تکمیل شوند.

### قابلیت‌های واقعی نسخه

| کار | رفتار پیاده‌سازی‌شده |
| --- | --- |
| اتصال سایت | ورود و رضایت OAuth، سپس تأیید مدیر وردپرس در مرورگر؛ کد یک‌بارمصرف وارد چت نمی‌شود. |
| محتوا | خواندن نوشته و برگه، ایجاد و ویرایش پیش‌نویس، انتشار صریح، تغییر محتوای منتشرشده و انتقال به زباله‌دان یا بازیابی با مجوز مناسب و بررسی نسخه. |
| سئو | خواندن و ویرایش فیلدهای پشتیبانی‌شده هر نوشته یا برگه در Yoast SEO و All in One SEO؛ نسخه محتوا و نسخه سئو باید هر دو منطبق باشند. |
| فایل ZIP پیوست | دریافت فایل واقعی ChatGPT، نگهداری موقت برای همان سایت، بررسی نام، نسخه و SHA-256. حداکثر فایل ۵۰ MiB و اعتبار لینک موقت ۳۰ دقیقه است. |
| نصب بسته | اجازه جداگانه نصب و مدیریت سایت در وردپرس، مجوز بومی وردپرس، تأیید کاربر و تطبیق هش؛ نصب بدون جایگزینی فایل موجود و بدون فعال‌سازی خودکار. |
| مدیریت نصب‌شده‌ها | فعال‌کردن پوسته یا افزونه نصب‌شده و غیرفعال‌کردن افزونه مجاز، با ابزار و تأیید جداگانه. |
| وضعیت | نمایش سایت‌های متصل، ظرفیت مستقل هر سایت، کارهای در انتظار و نتیجه عملیات. |

۳۵ ابزار عمومی با نام و ورودی مشخص وجود دارد. اجرای عمومی PHP، شل یا SQL، حذف دائمی، اجرای دلخواه REST یا Ability و ویرایش ساختار Elementor، Divi، Bricks یا WPBakery در این نسخه ارائه نمی‌شود. سئوی سراسری، تنظیم سایت‌مپ و همه امکانات تجاری Yoast/AIOSEO نیز وعده داده نشده‌اند؛ برای هر سایت باید خروجی `supported_fields` بررسی شود.

درج یک کار خواندن در صف هم روی سرور رکورد و رزرو سهمیه ایجاد می‌کند؛ بنابراین نشانه `readOnlyHint` آن عمداً `false` است. بررسی ساختار ZIP نیز تضمین سلامت امنیتی یا مجوز استفاده از کد داخل آن نیست.

## فایل قابل ارسال و بررسی فنی

در مخزن MCP این دستورها را اجرا کنید:

```sh
npm ci --no-audit --no-fund
npm run build
npm test
python3 tests/check_protocol.py
python3 tests/check_marketplace.py
python3 scripts/build_review_fixtures.py
python3 scripts/build_plugin.py
```

فایل خروجی:

`dist/wordrava-chatgpt-plugin-1.1.1-review-draft.zip`

دو manifest باید مستقیماً در ریشه ZIP باشند. هیچ رمز، توکن، کد اتصال مرورگر یا اطلاعات ورود داور را داخل ZIP یا Git نگذارید. بسته عمومی فقط manifestها و فایل‌های برند را دارد؛ فایل‌های آزمایشی وردپرس جدا هستند.

آزمون MCP با SDK واقعی و یک Center آزمایشی HTTPS اجرا می‌شود و قرارداد، مجوزها، ورودی فایل، تعارض نسخه سئو، هش بسته، تکرار درخواست و خطاهای امن را بررسی می‌کند. این آزمون جای نصب واقعی روی وردپرس یا بررسی پورتال OpenAI را نمی‌گیرد. پس از استقرار هماهنگ نسخه 1.1.1، دستور `python3 scripts/pre_submit_check.py` نسخه سرویس‌ها، اطلاعات OAuth و دسترس‌پذیری صفحات عمومی را کنترل می‌کند.

## کاربر نهایی چه چیزی وارد می‌کند؟

کاربر نصب‌کننده از فهرست عمومی، **آدرس سرور، Client ID یا scope وارد نمی‌کند**. این اطلاعات از قبل داخل `mcp.json` هستند. کاربر WordRava را نصب می‌کند، **Connect** را می‌زند و مجوزها را در مرورگر می‌پذیرد.

برای اتصال وردپرس، افزونه Connector را نصب می‌کند، صفحه **WordRava → Quick Connect** را در مدیریت وردپرس باز می‌کند و **Continue in browser** را می‌زند. مشخصات سایت را در Center بررسی و سپس درخواست را در مدیریت وردپرس تأیید می‌کند. در پایان با ابزار فهرست سایت‌ها اتصال بررسی می‌شود. دسترسی نوشتن همچنان نیازمند اجازه مشخص مدیر سایت و تأیید همان تغییر است.

پیکربندی ناشر در بسته:

| گزینه | مقدار |
| --- | --- |
| MCP | `https://wordrava.shayanostovar.com/mcp` |
| OAuth issuer | `https://wordrava.shayanostovar.com` |
| Authorization | `https://wordrava.shayanostovar.com/oauth/authorize` |
| Token | `https://wordrava.shayanostovar.com/oauth/token` |
| Client | `provided` / `wordrava-chatgpt` |
| Token authentication | `none`؛ بدون Client Secret |
| محافظت | PKCE S256 و redirectهای دقیق مجاز |
| callback ثابت ثبت‌شده | `https://chatgpt.com/connector_platform_oauth_redirect`؛ با مقدار دقیق پورتال تطبیق دهید |
| دسترسی اولیه | `sites:read content:read` |
| دسترسی اضافه نوشتن | `content:write` هنگام نیاز |

این روش ثبت‌شده در [مستندات احراز هویت](https://developers.openai.com/plugins/build/auth) پشتیبانی می‌شود؛ برای این تنظیم، DCR اجباری نیست. **callback دقیق نمایش‌داده‌شده در پورتال** باید در فهرست مجاز OAuth ثبت شود. شناسه callback را حدس نزنید و wildcard اضافه نکنید. میزبان ممکن است callback اختصاصی اتصال را به‌جای آدرس ثابت نمایش دهد.

## مراحل مالک برای ارسال عمومی

1. وارد [پورتال Plugins](https://platform.openai.com/plugins) شوید و سازمان، پروژه و هویت ناشر را انتخاب کنید؛ ZIP را بارگذاری کنید.
2. یافته‌های **Metadata & Skills** را بررسی و خطاهای بسته را اصلاح کنید.
3. در **MCPs**، سرور موجود در بسته را متصل کنید؛ callback دقیق و چالش دامنه را تکمیل و OAuth را تأیید کنید.
4. اسکن ابزارها را روی نسخه مستقر اجرا کنید و خطاهای مسدودکننده را برطرف کنید.
5. در **Review information → Review details**، اطلاعات واقعی ورود داور و لینک ویدئوی قابل دسترس را ثبت کنید؛ پنج سناریوی مثبت و سه سناریوی منفی بسته را اجرا کنید.
6. نسخه انتخاب‌شده را برای بررسی بفرستید. پس از تأیید، **Publish** را بزنید؛ تأیید به‌تنهایی انتشار عمومی نیست.

جزئیات مسیر در [راهنمای رسمی ارسال](https://developers.openai.com/plugins/deploy/submission) است. برای چالش دامنه، فقط توکن واقعی ارائه‌شده را به‌صورت متن ساده در مسیر نشان‌داده‌شده `/.well-known/openai-apps-challenge` قرار دهید. توکن ساختگی یا JSON معتبر نیست و نباید توکن اتصال دیگری را جایگزین کنید.

طبق [الزامات داوری MCP](https://developers.openai.com/plugins/deploy/app-review)، هویت ناشر باید تأیید شود؛ مالک سازمان یا کاربر دارای Apps Management Write می‌تواند ارسال کند. در حال حاضر پروژه با اقامت داده EU برای ارسال MCP پشتیبانی نمی‌شود و پروژه global لازم است. انتخاب و تأیید این موارد در اختیار مالک حساب است.

## آماده‌سازی سایت داوری

اپراتور می‌تواند از محیط اجرای مجاز Center، یک حساب مخصوص داوری با نقش عادی و **بدون دسترسی ادمین سنتر** بسازد:

```sh
dotnet WordRavaCenter.dll create-review-user
```

دستور تعاملی است؛ ایمیل و رمز واقعی داور را در پاسخ به پرسش‌های آن وارد کنید، نه در آرگومان خط فرمان یا Git. هنگام OAuth گزینه **ورود با حساب موجود WordRava** را انتخاب و با همان حساب وارد شوید. سایت نمونه را در همان مرورگر متصل کنید. داور هم باید همین ورود با حساب موجود را انتخاب کند تا در مرورگر تازه، سایت آماده را ببیند و یک حساب بدون رمزِ خالی ساخته نشود.

یک سایت HTTPS جدا با داده نمونه بسازید. Connector 1.1.1 را نصب و با حساب مخصوص داوری جفت کنید. رمز و روش ورود را فقط در فرم امن داوری وارد کنید. ورود داور باید بدون شبکه خصوصی، کد ایمیل/SMS، تأیید MFA یا magic link کار کند؛ حساب واقعی مشتری برای این کار مناسب نیست.

یک پیش‌نویس نمونه و یک افزونه سئوی پشتیبانی‌شده فعال داشته باشید. برای آزمون هر دو آداپتر، سناریوی سئو را جداگانه برای هرکدام اجرا کنید؛ اگر هر دو فعال‌اند، ارائه‌دهنده را صریح انتخاب کنید. فقط اجازه‌های لازم برای هر سناریو را در وردپرس روشن کنید.

فایل‌های `review/fixtures/` بسته‌های آزمایشی کوچک و قابل بازتولید هستند. افزونه آزمایشی هیچ hook، تماس شبکه یا تغییر داده‌ای ندارد. پوسته باید پس از نصب غیرفعال بماند. لینک پیوست‌ها بعد از انتشار همین نسخه مخزن واقعی می‌شود. برای تکرار نصب موفق، مدیر سایت آزمایشی می‌تواند فقط همان بسته آزمایشی غیرفعال را از داخل وردپرس حذف کند؛ ردکردن نصب روی پوشه موجود رفتار عمدی است.

در ویدئو، دریافت فایل، بررسی مشخصات و هش، توقف برای تأیید، نصب، نتیجه صف و ثابت‌ماندن وضعیت فعال‌سازی را نشان دهید. ردشدن مجوز ناکافی، نسخه قدیمی سئو، هش تغییریافته و دسترسی به سایت کاربر دیگر را هم ثبت کنید. توکن‌ها و fragment اتصال مرورگر نباید در ویدئو دیده شوند.

## مواردی که باید با اطلاعات واقعی مالک تکمیل شوند

[سایت](https://wordrava.shayanostovar.com/)، [حریم خصوصی](https://wordrava.shayanostovar.com/privacy)، [شرایط](https://wordrava.shayanostovar.com/terms) و [پشتیبانی](https://wordrava.shayanostovar.com/support) باید عمومی و مطابق عملکرد واقعی باشند. نام قانونی یا ایمیل پشتیبانی حدسی وارد نکنید.

سیاست حریم خصوصی باید نوع داده، هدف، گیرندگان، مدت نگهداری و کنترل‌های واقعی کاربر را توضیح دهد. درخواست حذف باید از مسیر عملی پاسخ داده شود. [قواعد افزونه](https://developers.openai.com/plugins/plugin-guidelines) و [راهنمای حریم خصوصی](https://developers.openai.com/plugins/guides/security-privacy) الزام جداگانه‌ای برای ابزار حذف حساب در چت تعیین نکرده‌اند؛ فرایند پشتیبانی مستند یک انتخاب اجرایی است. اطلاعات خصوصی یا کلید اتصال را در issue عمومی GitHub نخواهید.

موارد باقی‌مانده برای مالک عبارت‌اند از هویت تأییدشده OpenAI، پروژه مناسب، callback و چالش واقعی پورتال، حساب و سایت داوری قابل استفاده، ویدئوی واقعی، مسیر خصوصی رسیدگی به درخواست‌های حساس و تأیید نهایی صفحات حقوقی. هیچ‌کدام با ساخت ZIP یا انتشار main خودکار کامل نمی‌شوند. فیلد `demo_recording_url` تا زمانی که ویدئوی واقعی وجود ندارد عمداً خالی از داده ساختگی مانده است.

ترجمه فارسی فهرست داخل `publication.translations.fa-IR` قرار دارد. طبق رفتار فعلی واردکننده، نگهداری این ترجمه در بسته به معنی نمایش قطعی آن در فهرست عمومی نیست. صفحات فارسی و انگلیسی خود WordRava و نسخه‌های زبانی Connector مستقل از این محدودیت هستند.
